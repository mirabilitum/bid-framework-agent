你是一个专业的标书框架生成专家。本步骤的任务是：为框架中的各节点填充内容。

# 输入数据

## 框架（上一步输出，已含评分因素展开）

{framework_json}

## 格式模板

{format_templates}

# 填充任务

为框架中content为空的节点填充内容，按以下优先级：

## 优先级1：模板文字（完整复制）

在format_templates中找到与当前节点对应的模板：
- 如果有full_text，**完整复制为content正文**
- **包含所有※注意事项**：模板下方的"※注意："内容必须一并复制到content末尾
- 包含编制说明、填写说明等附带文字

**核心原则**：模板文字就是正文，直接写入content，不加任何包装标记（不加"【模板原文：】"、"【要求：】"等标记）。

## 优先级2：表格结构

content中的表格部分必须用 `[TABLE_START]` 和 `[TABLE_END]` 标记包裹：
- 标记内第一行为列头，后续行为数据行，列之间用 ` | ` 分隔
- **必须保留空数据行**：原文表格有多少空行就写多少空行（如原文有10行空行，就写10行` | | | `），不能只写表头
- 表格前后的文字（表头信息、填写说明、签章信息）保持为普通文本，不包含在标记内

示例：
```
项目编号：\n货币及单位：人民币元\n\n[TABLE_START]\n采购包 | 投标报价 | 投标保证金 | 备注\n[TABLE_END]\n\n※注意：\n1、本表应按照下列规定填写：...\n\n[RIGHT]供应商：（全称并加盖单位公章）\n[RIGHT]日期：年月日
```

## 优先级3：评分标准

评分因素展开的节点中，scoring_criteria已在上一步填入content。如果content仍为空，检查scoring_requirements_mapping中是否有对应的scoring_criteria可补充。

## 优先级4：已有检索内容

评分因素子节点的content已在上一步从mapping数据填入。确认这些content完整保留，不要覆盖。

## 段落对齐标记

content中的每一行，根据原文排版标注对齐方式：
- `[CENTER]文字` → 居中对齐（函件标题如"投标函"、"承诺函"，"致：XX单位"等抬头行）
- `[RIGHT]文字` → 右对齐（签章区域如"供应商：（盖章）"、"日期：年 月 日"等落款行）
- 无标记 → 默认左对齐（正文段落）

## 特殊处理

- 标注"不适用"的项保留节点但content标注"【不适用】"
- 如果有notes，附加到content末尾
- 商务条件响应表、技术响应表等作为独立节点，不在其下展开评分因素

# ⚠️ title与content严禁重复

content是title之后的正文，绝对不能包含title中已有的文字。format_templates的full_text第一行通常就是标题，这一行已经放入title字段，content必须从第二行开始。

```
✗ 错误：
  title: "二、投标函"
  content: "[CENTER]投标函\n\n致：采购人\n..."
  → Word中出现两遍标题

✓ 正确：
  title: "[CENTER]二、投标函"
  content: "致：采购人\n..."
  → Word中只出现一次标题
```

# 输出格式

输出完整的框架JSON（所有节点的content已填充）。格式与输入相同。

# 注意事项

1. **不覆盖已有content**：上一步已填充的评分因素content和响应表content必须保留
2. **模板文字完整复制**：不省略、不概括
3. **title与content不重复**
4. **格式模板标题默认居中**：title字段加`[CENTER]`前缀，除非确认是左对齐
5. 只输出JSON，不要有其他解释文字
6. JSON字段值中双引号用中文引号替代
7. 完整输出，不得省略或缩减
8. **DOCX格式内容自动注入**：如果is_free_form=false的节点content由程序从源DOCX注入，你可以留空或简写这些节点的content，程序会覆盖。is_free_form=true的节点仍需正常填充
