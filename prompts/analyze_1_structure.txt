# 提取任务

请从招标文件中提取以下4类信息，以JSON格式输出。

## 1. 项目基本信息

- 项目名称（完整准确）
- 采购方式（公开招标/竞争性磋商/询比采购等）
- 预算金额（如有）

## 2. 包信息（如有多包）

- 识别文档中是否包含多个采购包
- 每个包的编号、名称、预算
- 包的关键字：包、标包、采购包、Package等
- **评分标准一致性判断**：如果多个包共用同一套评分标准（评分因素、分值、评分细则完全相同），标注 `"scoring_shared": true`；否则标注 `"scoring_shared": false`

## 3. 评分标准（重点）

从评标办法、评审标准、评分因素等章节提取。

每个评分因素包含：
- name：名称（如"培训服务方案"）
- score：分值（数字，如25.0）
- category：类别（technical技术/commercial商务/price价格）
- description：**完整的评分细则原文**（不是简要说明，必须逐字复制评分表中的描述，包括得分档次、扣分规则、引用的章节号等）
- sub_items：子项列表（如有，如["培训目标", "培训对象"]）

**关键要求**：
- **正文和表格都要检查**：如果正文中只有大项总分（如"技术项78分"）而没有评分细项，必须到下方"表格内容"中查找包含"分值"/"得分"列的表格，评分细项可能在表格中
- description必须是评分表中的完整原文，不得概括或缩写。后续步骤依赖description中的信息（如章节引用、子项列举）进行全文检索
- 价格分不需要展开子项
- 识别父子评分结构（如"服务部分65分"包含多个子项）
- 所有分值必须是数字类型

**无评分表时的兜底**：当文档无分值型评分表时（如最低评标价法），**跟随文档自身的指引**找到评审依据——文档会告诉你评审标准在哪个章节、采购内容在哪个章节。从评审章节中提取与响应方案相关的审查条目（跳过程序性条目），从采购内容章节中提取对应的具体要求，两者关联后输出为scoring_factor格式（score=0, category="compliance_technical", source="compliance_review"），sub_items从原文中的列举提取。

## 4. 响应文件格式要求

### 4.1 查找并原封不动提取"投标文件组成"（skeleton）

**核心原则**：找到招标文件中关于"投标文件组成"/"响应文件组成"的章节，**原封不动地提取其结构和文字**，不修改、不重组、不重新编号。

**查找位置**（按优先级）：
1. "投标文件组成"/"响应文件组成"/"投标文件应包括下述部分"章节
2. "投标文件编制要求"/"响应文件编制要求"章节
3. 如果以上都找不到，从"投标文件格式"章节中提取
4. 如果以上都找不到，检查"符合性审查"/"符合性检查/采购需求"/"比选需求"/"服务需求"等章节中查找是否有明确的多级标题结构，可作为skeleton来源
5. 如有多个章节包含明确的多级结构，与评分表中的内容**综合比对**，取更完整、层级更清晰的版本

**提取要求**：
- **原封不动**：保留原文的编号格式（一、(1)、①、1.、格式一等）和标题文字
- **保留层级**：如果原文有嵌套结构，保留这个层级
- **不得重组**：不要按"资格/报价/技术"重新分组
- **不得遗漏**：每一项都必须提取
- **不得替换**：不要把概括性标题展开为具体子项列表

**常见结构类型**（供识别参考）：

嵌套结构示例：
```
（1）资格及资信证明部分
  ①响应函
  ②供应商的资格及资信证明文件
（2）报价部分
  ①开标一览表
```
→ 输出：`[{"title": "（1）资格及资信证明部分", "items": ["①响应函", ...]}, ...]`

扁平结构示例：
```
1.投标书
2.开标一览表
3.分项报价表
```
→ 输出：`["1.投标书", "2.开标一览表", ...]`

### 4.2 提取格式模板内容（format_templates）

如果招标文件有"投标文件格式"/"附件格式"等章节，提取每个模板的完整内容。

**必须提取完整正文，不是简要描述**：

| 模板类型 | 提取内容 |
|---------|---------|
| 投标函/响应函 | **全文**（含所有承诺条款、签章处） |
| 承诺函/声明函 | **全文**（含所有承诺事项） |
| 授权书 | **全文**（含授权范围） |
| 中小企业声明函 | **全文**（含声明条款和表格） |
| 表格模板（开标一览表等） | **表头列名+列说明** |
| 封面格式 | **完整格式**（含所有字段） |
| "内容格式自拟"项 | 标注为自拟，不提取模板 |

**段落对齐标记**：提取full_text时，根据截图/格式信息标注对齐方式：
- `[CENTER]文字` → 居中的行（如函件标题）
- `[RIGHT]文字` → 右对齐的行（如签章落款）
- 无标记 → 默认左对齐（正文段落）
- 缩进用空格：一级2空格，二级4空格，三级6空格
- 表格用 `[TABLE_START]...[TABLE_END]` 包裹，列用 ` | ` 分隔

**DOCX文档特殊说明**：如果输入文档为DOCX格式，format_templates的full_text可以只写模板标题，程序会自动从源文档提取完整内容和精确格式。但skeleton、content_type、is_free_form等字段仍需完整提取。

**提取格式**：
```json
[
  {
    "id": "格式编号（如有）",
    "title": "模板标题",
    "content_type": "full_text / table_structure / cover_format / free_form",
    "full_text": "完整正文内容",
    "table_columns": "列名1 | 列名2（表格时使用）",
    "is_free_form": false,
    "notes": "附带说明"
  }
]
```

### 4.3 source字段

标注skeleton的来源：
- "detailed_list" — 找到详细的完整列表
- "compliance_table" — 从符合性审查表提取
- "requirements_structure" — 从采购需求章节提取
- "outline_plus_inference" — 找到大纲，推断补充
- "inferred" — 完全从评分因素推断

# 输出格式

请严格按照以下JSON格式输出，不要添加任何其他文字：

```json
{
  "project_info": {
    "name": "项目完整名称",
    "procurement_type": "采购方式",
    "budget": "预算金额（如无则为空字符串）"
  },
  "packages": [
    {"id": "1", "name": "包1名称", "budget": "包1预算"}
  ],
  "scoring_shared": true,
  "scoring_factors": [
    {
      "name": "评分因素名称",
      "score": 25.0,
      "category": "technical",
      "description": "评分细则完整原文",
      "sub_items": ["子项1", "子项2"]
    }
  ],
  "response_format": {
    "skeleton": "原封不动的投标文件组成结构",
    "format_templates": [],
    "source": "detailed_list"
  }
}
```

# 注意事项

1. 如果文档中没有多包，packages数组留空[]
2. 多包共用评分标准时scoring_factors只输出一份
3. 评分因素必须完整提取，不要遗漏
4. skeleton必须原封不动复制原文结构
5. format_templates模板文字必须完整提取（全文，不是摘要）
6. 所有分值必须是数字类型
7. 只输出JSON，不要有其他解释文字
8. JSON字段值中双引号用中文引号替代（避免破坏JSON格式）
9. 完整输出，不得省略或缩减
